What exists today, and what this design adds

The mockup gap: the October 2 Unlinked plan describes profile asks, but the visual overlay is predominantly notes, cadence and links. It does not yet treat a standing ask for a nonmember as a first-class person-linked record.

Chet’s current saved data: a private Noos note with label “ask”, CRM/standing-ask tags, a parent person record, and an owner-private overlay note pointing back to it. The standing status and beneficiary are recorded in its text. It is not a published OpenChat AgentIntent, and this prototype does not change its storage.

LayerTodayProposed addition
OpenChat asksStructured intents: terms, owner, status, expiry, goals, seeks, brings, matching mode and close-on-connect.A stable subject person distinct from recorder/account owner.
Private person contextNamed entities, notes and links. No native ask type in the people overlay.Typed private asks with lifecycle, location, duration and source.
Profile displayMember profiles already show Stories via /api/stories/feed?author=… in enhanced mode. No separate profile-asks endpoint is needed.Add private “asks I’m keeping” beside the existing author-shared asks, including for people without linked accounts. Enforce visibility before rendering.
PublicationDrafts, audience-gated Stories and explicitly enabled quiet search.A private ask can be the source of an explicitly approved publication owned by the publisher; never expose private fields or notes through that publication.
IdentityOverlay entities support multiple app references.Attach a verified account/profile to the same person. No name-only auto-claim and no automatic ownership transfer.

Minimum structured record: ask ID · subject person ID · recorder/owner ID · terms · place · active/paused/closed status · standing or time-bound duration · expiry · close-after-introduction choice · source · confirmation state · created/updated timestamps. Private visibility and any publication IDs are explicit. Agents can then answer “who wants to meet people in Sacramento?” without extracting the answer from arbitrary notes each time.

Implementation boundary: these cards, the For people collection and person-based ask associations are proposed. No production code, schema, messages, permissions or stored asks were changed. Prototype additions disappear on reload.
