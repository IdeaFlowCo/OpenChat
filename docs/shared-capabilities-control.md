# Shared Control/OpenChat capabilities v1

Implementation owner Control Sol f7ade329. OpenChat tickets OpenChat-3dsp and OpenChat-vwgq.2; isolated branch feat/control-shared-capabilities. No Earmark source edits.

The assistant derives a scope from current membership and conversation type. Only the owner's exact two-participant direct assistant DM can be universal. Every group/inline turn is conversation-scoped; the tools catalog is filtered and execution independently denies any private-source/new tool and foreign target. Searches filter on conversation before retrieving results and omit global semantic search. Isolated conversation turns expose read tools only: send_message/post_context are denied even with model-supplied confirm:true; the assistant can still answer as itself. Pending human-send proposals are keyed by user AND originating private assistant conversation, never injected into another scope. Every call rechecks membership; a DM that becomes shared loses universal authority. Current message scope is persisted through both transports/outbox, authorizes each new turn without retroactively changing prior context, and can narrow the DM using the labelled composer control. The shared send boundary snapshots the selected chat scope for text, photos, files/captions, and emoji; recordings retain their scope from start through upload even if the composer changes. Each delayed assistant trigger carries its persisted originating message ID, validates chat/actor/membership, derives authority from that message, and bounds context to it. Other messages sharing its timestamp are conservatively omitted. Quoted reply ancestry is server-resolved, membership-filtered, bounded to three levels/3000 excerpt characters and cycle-protected. Unavailable ancestors expose no metadata. Existing replyToId transport remains canonical.

`POST /api/vision/connection` starts/reuses an owner-consented Vision-only personal connector grant. The key stays encrypted on the server using the existing OC_KEY_ENCRYPTION_SECRET with per-owner authenticated encryption. The response returns only the approval URL and comparison code. Sign in with the same Ideaflow ID and explicitly tick Vision write. This reuses existing `/agent/keys/request`, `/agent/keys/status` and `/mcp`; no new write proxy or built-in secret is needed. `/builtin-agent/read` remains read-only. Neither a native ID token, an email match, nor service-key possession establishes Vision write authority.

`POST /api/vision/saves` uses the authenticated human's local identity (no client/model owner field), body `{destination:'vision',kind,title,body,sourceRefs,visibility:'private',idempotencyKey}`. Each source ref supplies `sourceDigest`, the lowercase SHA-256 of the full message content (or transcript if content is empty). New writes require matching digests and current membership, rechecked after grant validation and reservation immediately before dispatch; excerpts must still be actual substrings. Legacy versionless requests are accepted only for matching historical receipt lookup, never a new dispatch. Versioned payload hashes include the digest; matching legacy receipt hashes remain readable by upgraded clients. Grant issuer+subject must exactly match the persisted local identity and read/write permissions are checked fresh. No agent/model tool can invoke this human Save route. Current ordinary connector write does not accept an idempotency key: server stores the attempt before dispatch, embeds an opaque provenance marker in the note body, and only reports saved after persisting a durable destination ID. A duplicate key returns its existing receipt, a different payload is rejected, and lost destination/ledger acknowledgments retain the original uncertain receipt. The UI offers Open Vision and an explicit duplicate-warning confirmation to Save a new copy with a new UUID; the original is never silently retried. Existing matching owner receipts are returned before rechecking source/linkage/grants, so deleting a source or revoking a grant cannot erase a prior saved receipt. New saves/copies always recheck current source ACL and grant. Nothing automatically retries an uncertain write. WikiHub/Noos writes are unavailable.

Receipt `{status:'saved'|'rejected'|'needs_auth'|'unavailable'|'uncertain',destinationId?,url?,savedAt?,reason?}`. A saved result requires a real note ID. Missing linkage keeps the selection in the action sheet; no real user note/message is used as a test. UI offers full answers and exact selected excerpts, private by default, and returns a destination link. A stale source is rejected. OpenChat's existing tokens, UI tokens, app identity, and user data are preserved.
