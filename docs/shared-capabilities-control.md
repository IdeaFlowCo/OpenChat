# Shared Control/OpenChat capabilities v1

Implementation owner Control Sol f7ade329. OpenChat tickets OpenChat-3dsp and OpenChat-vwgq.2; isolated branch feat/control-shared-capabilities. No Earmark source edits.

The assistant derives a scope from current membership and conversation type. Only the owner's exact two-participant direct assistant DM can be universal. Every group/inline turn is conversation-scoped; the tools catalog is filtered and execution independently denies any private-source/new tool and foreign target. Searches filter on conversation before retrieving results and omit global semantic search. Every call rechecks membership; a DM that becomes shared loses universal authority. Current message scope is persisted through both transports/outbox, affects that turn only, and can narrow the DM using the labelled composer control. Quoted reply ancestry is server-resolved, membership-filtered, bounded to three levels/3000 excerpt characters and cycle-protected. Unavailable ancestors expose no metadata. Existing replyToId transport remains canonical.

`POST /api/vision/connection` starts/reuses an owner-consented Vision-only personal connector grant. The key stays encrypted on the server using the existing OC_KEY_ENCRYPTION_SECRET with per-owner authenticated encryption. The response returns only the approval URL and comparison code. Sign in with the same Ideaflow ID and explicitly tick Vision write. This reuses existing `/agent/keys/request`, `/agent/keys/status` and `/mcp`; no new write proxy or built-in secret is needed. `/builtin-agent/read` remains read-only. Neither a native ID token, an email match, nor service-key possession establishes Vision write authority.

`POST /api/vision/saves` uses the authenticated human's local identity (no client/model owner field), body `{destination:'vision',kind,title,body,sourceRefs,visibility:'private',idempotencyKey}`. Sources are membership-checked again; excerpts must still be actual substrings. Grant issuer+subject must exactly match the persisted local identity and read/write permissions are checked fresh. No agent/model tool can invoke this human Save route. Current ordinary connector write does not accept an idempotency key: server stores the attempt before dispatch, embeds an opaque provenance marker in the note body, and only reports saved after persisting a durable destination ID. A duplicate key returns its existing receipt, a different payload is rejected, and lost destination/ledger acknowledgments remain uncertain forever until explicit reconciliation. Nothing automatically retries an uncertain write. WikiHub/Noos writes are unavailable.

Receipt `{status:'saved'|'rejected'|'needs_auth'|'unavailable'|'uncertain',destinationId?,url?,savedAt?,reason?}`. A saved result requires a real note ID. Missing linkage keeps the selection in the action sheet; no real user note/message is used as a test. UI offers full answers and exact selected excerpts, private by default, and returns a destination link. A stale source is rejected. OpenChat's existing tokens, UI tokens, app identity, and user data are preserved.

Executable fixtures: `apps/server/test/visionSave.test.ts`, `assistantScope.test.ts`, and `assistantScope.execution.test.ts`. Current results are local fixture evidence; deployment/native/UI/real consent acceptance are separate stages. Earmark can reuse the request/receipt semantics and existing connector capability; no Control navigation or broad grant is required. G-ID production native registration and G-AMBIENT live Archive writes remain held. No Archive mirroring or main-stream promotion is activated.
