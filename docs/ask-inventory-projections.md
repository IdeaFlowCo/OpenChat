# Federated ask inventory adapters

`services/askInventorySources.ts` defines the read-only adapter boundary. It does not create source connections or claim those adapters are deployed. One authoritative writer remains responsible for each record. The owner view may render source references without copying records into an ask database. Unavailable is distinct from an empty page; source/filter/viewer-bound cursors and upstream ACL checks happen before pagination. Dedupe uses typed source IDs and verified lineage, never fuzzy title matches.

- **Unlinked:** extend the established owner-only no-store private-context adapter to read canonical owner asks. Put All asks on the authenticated profile even without `ownProfileId`. Viewer profile sections use authorized publication reads. Social Looking for/About sections stay public source references; explicit promotion may save/link one ask with section ID/revision. A profile URL, private contact or email never establishes ownership or grants access.
- **Social:** public About bullets remain `ideaflow.profile.v1` projections. Owner/private reads and published viewer reads are separate; a public bullet is not permission to republish unrelated private evidence. Use the verified existing profile entry, not duplicate people or stores.
- **World Issue Tracker:** retain native issue status, store and write APIs. The adapter reads viewer-authorized `/me` references (authored anywhere union attached to personal tracker) with bounded cursors/availability. Only explicit promotion/known binding links a canonical ask to an issue. A marketing ask mentioning worldissuetracker.com is not automatically an issue. Fulfilled and resolved are not mechanically synchronized.
- **Gestalt:** retain caring, carrying, placing, sharing and mentioning as distinct facts. Start with a read-only adapter to this interface; sample/localStorage prototype data is not production authority. Reuse verified identity and publication boundaries; create no separate group roster or ask store.

Publication and matching are separate channels. A later explicit Story/matching action may attach a verified owner-only output link after that service succeeds. Failed writes attach no lineage. This contract introduces no imports, background synchronization, publishing or notifications.
